## 纪律一:动了对外行为 → 走带 e2e 的图(开票时选)

**规则**:凡改动会变更可观察行为——新端点、改协议/契约/语义、改所有权
或围栏规则、新对外能力——开票时 `bundle_name` 必须选**带 e2e-author 的图**
(当前是 feature-full,其 verification 同时复跑作者场景;也可以给别的图加这一步,加步零代码)。

纯重构、纯文档、明显不碰行为面的 chore → 现有图照旧(存量套件+verification
已够)。

**判断口诀**:问"这个改动合入后,现有 40 场景测不出、但用户/调用方能感知
的差异是什么?"——答得上来就必须出**新**考题;答不上来,存量网够用。

**边界情况**:一张小票中途发现动了行为面(grill/spec 阶段才看清)→
agent 在 needs_input 里申报,由 owner 决定"转图重开"还是"人补场景"。

## 纪律二:修 bug → 复现必须沉淀为回归测试(bug-fix 图内硬化)

**规则**:bug-fix 的 `fix` 步产出**必填** `regression_test` 字段——
repro 步的复现必须固化为"改前失败、改后通过"的测试,进树、被
verification 跑、被 review 盯。豁免必须显式 `waived: <理由>`,
豁免对 review 可见、会被挑战。

**理由**:bug 修完没有测试钉住,等于没修——同一个 bug 的下一次回归只靠
人眼。复现即考题,修完即答案,考题进树就是永久资产。

(已落地:`workflows/bug-fix/steps/fix.md` + `workflow.md` 产物表。)

## 纪律三:skill / 提示词逻辑变动 → 必跑真票观察窗(运营规程)

**规则**:任何合入触及以下文件,在下一个 cutover 级发布**之前**,必须
跑一轮真票观察窗并收门槛读数:

```
触发面:
  workflows/*/steps/*.md              (步骤岗位说明 = 提示词逻辑)
  workflows/*/workflow.md             (图结构改动:步序/门/回退边)

窗口规程(照 v1.5 重观测窗的既有实践):
  1. 起干净 rig,发 ≥10 张真票(混合 bundle 类型,含 ≥1 张会触发
     改动面的票)
  2. needs_input 一律 owner 直答
  3. 收数:V4(证据门)、V8(同步链)、恢复/blocked 计数、孤儿数
  4. 与上一窗读数对比:无回退 → 过;回退 → 冻结合入、先修
  5. 报告落 docs/pilot/,读数不改历史
```

**理由**:提示词改动单测测不了,它的 e2e 只能是真 agent 真票。本轮
session 已经用这个方法验证过两次(SKILL.md v1.5 化后的 40 票窗口、
窗口交付物合入后的回归),本条把它从"实践"升为"规程"。

## 检查单(合入 review 用)

```
[ ] 动了行为面?→ 选了带 e2e 的图 / 或人补了新场景
[ ] bug 修复合入?→ regression_test 字段非空或豁免理由被 review 接受
[ ] 触发了 skill 面?→ 登记观察窗票(不阻塞合入,阻塞 cutover 级发布)
```
